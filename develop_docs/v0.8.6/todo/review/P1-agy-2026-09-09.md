### 2. `tests/parity_fuzz.py` 내 rerank 점수 `NaN` 허점 잔존
- **위치**: `tests/parity_fuzz.py:34-46`
- **문제**: 1차 codex 리뷰 지적(MAJOR-3)에 따라 `tests/parity.py`와 `golden.test.ts`에서는 `NaN` 검증을 보강(`re.fullmatch(r"-?\d+\.\d")` 및 `math.isfinite`)했으나, P1-49+로 추가된 차등 퍼징 도구 `tests/parity_fuzz.py`의 `rerank_ok()`에는 동일한 `NaN` 허점이 여전히 방치되어 있다. Node 출력이 `NaN`을 반환하더라도 `abs(float(x) - float("nan")) > 0.05` 연산이 `False`를 반환하여 테스트가 잘못 통과된다.
- **근거**:
  - Python 정본 검증기 (`tests/parity.py:165-166`):
    ```python
    if not re.fullmatch(r"-?\d+\.\d", parts[1]) or not math.isfinite(float(parts[1])):
        return "error", f"line {i}: score not a finite .1f number: {parts[1]!r}"
    ```
  - 퍼징 검증기 (`tests/parity_fuzz.py:44`):
    ```python
    if abs(float(x[1]) - float(y[1])) > 0.05:
        return False
    ```
  - 재현: `python3 -c 'print(abs(1.2 - float("nan")) > 0.05)'` → `False` (불일치 판정 누락).
- **제안**: `tests/parity_fuzz.py`의 `rerank_ok`에 `math.isfinite(float(y[1]))` 및 형식 검증을 추가하여 `parity.py`와 동일한 검증 수준을 적용하라.

### 3. CI `npm pack` 가드 스크립트의 Windows 러너 경로/인라인 실행 결함 위험
- **위치**: `.github/workflows/ci.yml:62-78`
- **문제**: `ci.yml`의 `Pack content guard` 스텝이 `shell: bash` 환경에서 `$RUNNER_TEMP` 환경변수를 사용하여 `python - "$RUNNER_TEMP/npm-pack.json" <<'PY'` 형태로 실행된다. Windows 러너(Git Bash)에서 `$RUNNER_TEMP`는 POSIX 스타일 경로(`/d/a/_temp`)로 확장되는데, Windows 네이티브 `python.exe`에 인자로 넘겨질 때 경로 해석 오류가 발생하거나 heredoc 파이프 처리에서 실패할 위험이 있다.
- **근거**:
  - `.github/workflows/ci.yml:65-66`:
    ```yaml
    npm pack --dry-run --json --ignore-scripts > "$RUNNER_TEMP/npm-pack.json"
    python - "$RUNNER_TEMP/npm-pack.json" <<'PY'
    ```
- **제안**: 파일 I/O 대신 파이프로 직접 넘기거나(`npm pack --dry-run --json | node -e '...'`), 별도의 독립 Node 스크립트(`scripts/pack-guard.mjs`)로 분리하여 OS별 셸 및 파이썬 경로 차이에 의존하지 않도록 구성하라.
