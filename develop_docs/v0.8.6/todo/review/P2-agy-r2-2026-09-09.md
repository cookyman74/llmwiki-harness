#### 2. 동시성 세마포어(`acquire`/`release`)의 마이크로태스크 레이스 및 큐 추월(Queue Jumping)
- **위치**: [`tools/llmwiki-mcp/src/server.ts:30-46`](file:///Users/junghojang/Developments/myProject/obsidian_llmwiki/tools/llmwiki-mcp/src/server.ts#L30-L46)
- **문제**: `release()` 함수에서 큐 대기자(`waiters`)가 남아있는 상태에서도 `inFlight--`를 무조건 먼저 실행한 뒤 `next()`(Promise resolve)를 호출한다. JavaScript의 Promise 마이크로태스크 스케줄링 특성상, 깨어난 대기자가 `acquire()` 내부의 `inFlight++`를 실행하기 전에 새로운 요청이 동기적으로 `acquire()`를 호출하면 `inFlight < 4`로 판정되어 큐를 추월(Queue jumping)하여 진입한다. 그 직후 깨어난 대기자가 실행되면 일시적으로 `inFlight`가 `MAX_CONCURRENT_CALLS` (4)를 초과하여 5개 이상의 요청이 동시 처리될 수 있다.
- **근거**:
  - `src/server.ts:33-45`:
    ```typescript
    async function acquire(): Promise<void> {
      if (inFlight < MAX_CONCURRENT_CALLS) {
        inFlight++;
        return;
      }
      await new Promise<void>((resolve) => waiters.push(resolve));
      inFlight++; // <- release에서 inFlight-- 된 후 microtask에서 다시 증가
    }
    function release(): void {
      inFlight--; // <- 대기자가 있어도 먼저 3으로 감소
      const next = waiters.shift();
      if (next) next();
    }
    ```
- **제안**: 세마포어 슬롯 인계 패턴을 적용하여, 대기자가 있을 때는 `inFlight`를 감소시키지 않고 슬롯을 대기자에게 직접 인계하며, `acquire()`의 `await` 이후에는 `inFlight++`를 수행하지 않도록 수정하라:
  ```typescript
  async function acquire(): Promise<void> {
    if (inFlight < MAX_CONCURRENT_CALLS) {
      inFlight++;
      return;
    }
    await new Promise<void>((resolve) => waiters.push(resolve));
  }
  function release(): void {
    const next = waiters.shift();
    if (next) {
      next(); // 슬롯 직접 인계 (inFlight 수치 유지)
    } else {
      inFlight--;
    }
  }
  ```

- **근거**:
  - `src/tools.ts:341`:
