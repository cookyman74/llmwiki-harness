문제: opt-in에서 `structuredContent`는 반환하지만 `content[0].text`는 구조화 JSON 직렬화본이 아니라 TSV/Markdown 텍스트다. MCP 스펙은 structured output을 반환하는 도구가 하위호환을 위해 serialized JSON을 TextContent에도 넣도록 권고한다(SHOULD).

근거: [MCP 2025-06-18 Tools specification](https://modelcontextprotocol.io/specification/2025-06-18/server/tools)은 `outputSchema`를 선택 사항으로 규정하고, 선언 시 구조화 결과가 스키마를 만족해야 하며, structured output의 TextContent 직렬화를 하위호환 목적으로 권고한다. 따라서 기본 text-only는 스펙상 문제없고, opt-in의 선언·전송 pairing도 `createServer()` 경로에서는 맞다. 다만 현재 TextContent 형식은 권고와 다르다.

제안: 기존 텍스트 호환성을 우선한다면 의도된 예외라고 명시하라. structured 클라이언트 호환을 최우선으로 하면 TextContent에 JSON 직렬화본을 제공하는 별도 모드를 검토하라.

총평(병합 가능 여부)

현재 상태로는 병합 불가. 스펙상 기본 off 자체는 유효하고 `createServer()`의 `outputSchema`·`structuredContent` pairing도 맞지만, 텍스트 동등성 주장이 대형 응답에서 거짓이며 기본 경로가 전체 응답 상한을 우회한다. 또한 기존 상한·보안 테스트가 실제 기본 모드를 충분히 검증하지 않는다.
