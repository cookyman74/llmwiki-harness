### 1. CLI 인자 파서의 위치 의존성 결함으로 인한 `--root` 무음 유실 (Silent Fallback)
- **위치**: [`tools/llmwiki-mcp/src/cli.ts:78-86`](file:///Users/junghojang/Developments/myProject/obsidian_llmwiki/tools/llmwiki-mcp/src/cli.ts#L78-L86)
- **문제**: `cli.ts`의 `--once` 처리 로직이 `argv.indexOf("--once")`를 찾은 뒤 `argv.slice(onceAt + 2)`만을 `runOnce`로 넘긴다. 만약 사용자가 `llmwiki-mcp --root <vault> --once search <term>` 처럼 `--root` 플래그를 `--once` 앞에 배치하면, `--root` 인자가 완전히 유실되어 `runOnce`가 기본값 `root = "."`(현재 디렉터리)로 실행된다. 이로 인해 오류 없이 `no matches for: ...` 같은 빈 결과를 반환하는 무언의 실패(Silent failure)가 발생한다.
- **근거**:
  - `cli.ts:78-86`:
    ```typescript
    const onceAt = argv.indexOf("--once");
    if (onceAt >= 0) {
      const mode = argv[onceAt + 1];
      if (mode !== "search" && mode !== "expand" && mode !== "pack") {
        process.stderr.write("usage: llmwiki-mcp --once <search|expand|pack> [args…] --root <vault>\n");
        return 2;
      }
      process.stdout.write(await runOnce(mode, argv.slice(onceAt + 2)));
      return 0;
    }
    ```
  - **실행 재현**:
    ```bash
    # 1. --root가 앞에 위치한 경우 (버그 발생: root 인자 유실로 현재 디렉터리 . 에서 검색 → 미매치)
    node dist/cli.js --root test/fixtures/vault --once search rerank
    # 출력: no matches for: rerank (exit 0)

    # 2. --root가 뒤에 위치한 경우 (정상 동작)
    node dist/cli.js --once search rerank --root test/fixtures/vault
    # 출력: 1/7 concept-reranking concept ... (8개 행 출력)
    ```
- **제안**: `--once` 분기 내부에서 `argv` 전체를 대상으로 옵션을 파싱하거나, `argv.slice(onceAt + 2)` 대신 `--once <mode>`를 제외한 전체 인자 목록을 `runOnce`에 전달하도록 수정하라.

### 3. `capText`의 UTF-16 단순 `slice`로 인한 유니코드 서로게이트 쌍(Surrogate Pair) 파손 위험
- **위치**: [`tools/llmwiki-mcp/src/tools.ts:20, 288-291`](file:///Users/junghojang/Developments/myProject/obsidian_llmwiki/tools/llmwiki-mcp/src/tools.ts#L20), [`tools/llmwiki-mcp/src/tools.ts:288-291`](file:///Users/junghojang/Developments/myProject/obsidian_llmwiki/tools/llmwiki-mcp/src/tools.ts#L288-L291)
- **문제**: `TEXT_LIMIT` (200 * 1024) 절단 시 `text.slice(0, TEXT_LIMIT)`를 단순 실행한다. 만약 204,800번째 인덱스가 이모지나 non-BMP 유니코드 문자(서로게이트 쌍: High Surrogate `0xD800~0xDBFF` + Low Surrogate `0xDC00~0xDFFF`)의 중간에 위치할 경우, 잘린 문자열 끝에 Lone High Surrogate(`\uD83D` 등)가 남게 된다. 이는 JSON 직렬화 및 UTF-8 스트림 전송 시 비정형 유니코드(U+FFFD 치환 또는 엄격한 JSON 파서 오류)를 발생시킨다.
- **근거**:
  - `tools.ts:288-291`:
    ```typescript
    export function capText(text: string): { text: string; truncated: boolean } {
      if (text.length <= TEXT_LIMIT) return { text, truncated: false };
      return { text: text.slice(0, TEXT_LIMIT) + "\n…[truncated at 200 KB]\n", truncated: true };
    }
    ```
  - **재현 코드**:
    ```javascript
    const s = "a".repeat(200 * 1024 - 1) + "\uD83D\uDE00"; // 204800 경계에 이모지 배치
    const sliced = s.slice(0, 200 * 1024);
    console.log(sliced.charCodeAt(200 * 1024 - 1).toString(16)); // "d83d" (Lone High Surrogate 잔존)
    ```
- **제안**: `slice` 직전 경계 문자(`text.charCodeAt(TEXT_LIMIT - 1)`)가 High Surrogate 범위(`0xD800 <= c && c <= 0xDBFF`)인지 확인하여, 해당할 경우 `TEXT_LIMIT - 1`에서 자르도록 보정하라.

### 6. `TEXT_LIMIT`의 바이트 상한(UTF-8) vs 문자 상한(UTF-16) 괴리 및 대용량 한글 문서 전송량
- **위치**: [`tools/llmwiki-mcp/src/tools.ts:20`](file:///Users/junghojang/Developments/myProject/obsidian_llmwiki/tools/llmwiki-mcp/src/tools.ts#L20)
- **문제**: `TEXT_LIMIT = 200 * 1024`가 문자열의 `length`(UTF-16 코드유닛)로 정의되어 있어, 3바이트 UTF-8로 인코딩되는 한글 텍스트의 경우 실제 와이어 전송 크기가 최대 ~600KB까지 커질 수 있다. DESIGN §5의 "응답 텍스트 ≤ 200KB" 목표와 최대 3배의 차이가 발생한다.
- **근거**:
  - 10만 자 한글 문서 = `length: 100,000` (`<= 204,800`이므로 `truncated: false`), 그러나 UTF-8 바이트 크기는 약 300KB로 200KB를 초과함.
- **제안**: 현재 구현이 의도된 근사(주석 명시)임을 확인하였으나, 엄격한 200KB 전송량 상한이 필요한 클라이언트 환경을 감안하여 바이트 기준 절단(`Buffer.byteLength`) 적용 여부를 검토하라.
