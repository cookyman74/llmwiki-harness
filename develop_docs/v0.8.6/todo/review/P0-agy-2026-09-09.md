### [MAJOR] `tsconfig.json` 및 검증 스크립트의 `test/` 디렉터리 타입 검사 누락

- **위치**: `tools/llmwiki-mcp/tsconfig.json` 16행 (`"include": ["src"]`), `tools/llmwiki-mcp/package.json` 18~20행 (`scripts`)
- **문제**: TypeScript 컴파일 대상이 `src/`로만 한정되어 있어, `test/` 하위의 단위 테스트 코드(`test/unit/scaffold.test.ts` 및 향후 P1의 단위 테스트들)가 `tsc`의 정적 타입 검사 대상에서 완전히 제외되어 있습니다. 또한 `npm run lint`도 `eslint src`로만 지정되어 테스트 코드의 린트 및 타입 무결성을 검증하는 파이프라인이 누락되었습니다.
- **근거**:
  `tools/llmwiki-mcp/tsconfig.json`:
  ```json
  "include": ["src"]
  ```
  `tools/llmwiki-mcp/package.json`:
  ```json
  "scripts": {
    "build": "tsc",
    "test": "vitest run",
    "lint": "eslint src"
  }
  ```
  Vitest는 기본적으로 esbuild 기반 트랜스파일을 수행하므로 타입 에러가 있어도 런타임 오류가 없으면 테스트를 통과시킵니다. P1 단계에서 21개 포팅 대응표(#1~#21)를 검증하는 단위 테스트들이 대량 추가될 때, 테스트 코드 자체의 타입 오류나 인터페이스 불일치가 `npm run build`나 CI 빌드에서 잡히지 않는 사각지대가 발생합니다.
- **제안**:
  1. `tsconfig.json`의 `include`를 `["src", "test"]`로 지정하거나, 빌드용 `tsconfig.build.json`(`outDir: "dist"`, `include: ["src"]`)과 전체 검사용 `tsconfig.json`(`include: ["src", "test"]`)으로 분리하십시오.
  2. `package.json`에 `"typecheck": "tsc --noEmit"` 스크립트를 추가하고, `"lint"` 스크립트를 `"eslint src test"`로 확장하십시오.

### [MAJOR] `package.json` clean 스크립트의 Windows 환경 실행 실패 (작은따옴표 중첩)

- **위치**: `tools/llmwiki-mcp/package.json` 21행
- **문제**: `clean` 스크립트가 작은따옴표(`'`)를 중첩한 인라인 Node 스크립트로 작성되어 있어, Windows(`cmd.exe`) 환경에서 명령행 파싱 오류(`SyntaxError: Unexpected token`)가 발생합니다.
- **근거**:
  `tools/llmwiki-mcp/package.json` 21행:
  ```json
  "clean": "node -e \"require('node:fs').rmSync('dist',{recursive:true,force:true})\""
  ```
  DESIGN §7 및 §12에서 CI 3-OS(Ubuntu, macOS, Windows) 매트릭스 지원을 명시하고 있으나, Windows 명령 프롬프트는 작은따옴표를 문자열 구분자로 처리하지 않아 `node -e`에 전달되는 코드가 깨집니다.
- **제안**:
  작은따옴표 대신 이스케이프된 큰따옴표를 사용하거나 Node 스크립트로 분리하십시오:
  ```json
  "clean": "node -e \"require(\\\"node:fs\\\").rmSync(\\\"dist\\\",{recursive:true,force:true})\""
  ```
