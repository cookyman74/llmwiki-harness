# PRD — 질의 토큰·지연 최적화 (①②③)

- **버전 대상**: v0.8.x 후속 (질의 경로 리트리벌 최적화). ※문서 폴더명은 v0.8.3이나 v0.8.3은 이미 릴리즈됨 → 실제 배포 태그는 **v0.8.4 또는 v0.9.0**(질의 흐름 변경이라 minor 후보).
- **작성일**: 2026-08-01
- **범위**: wiki-query 스킬 · wiki-ops 오케스트레이터 · search.py (스크립트)
- **비대상**: LLM 모델 교체(별건·최후 카드), ④ query 환류 캐시(후속 PRD), 페이지 발췌 read(후순위)

## 1. 배경 / 문제

질의 응답이 질의당 토큰을 과다 소모한다. 실측(2026-08-01 두 질의):
- "클로드코드 사내 교육": subagent 61.8k tokens / tool_uses 19
- "차주 업무 준비": subagent 52.4k tokens / tool_uses 12

원인 진단(모델 아님 — 리트리벌 방식):

| 드라이버 | 실측 | 문제 |
|---|---|---|
| index.md 통독 | 218줄 / 22.6KB, **매 질의** | "빠짐없이" 카탈로그를 표적 질의에도 전량 read |
| 광역 탐색 | index→MoC 다수(claude-code-moc 98줄)→페이지 12~19 read | Read 왕복마다 오버헤드, 넓게 읽음 |
| 오케스트레이터 프롬프트 비대 | 후보 ~10 [[페이지]] 나열 + 장문 지시 | 입력토큰↑ + 나열분 전부 통독 유도 + 장문 출력 유도 |

핵심: 페이지 자체는 작다(30~60줄). 비용은 **크기가 아니라 넓게 읽어서** 발생한다.

## 2. 목표 (What)

1. **① 결정적 사전스코프**: 오케스트레이터가 질의 응답 전, 결정적 스크립트(토큰 0)로 관련 페이지 후보를 **먼저 좁혀** synthesizer에 표적 목록으로 전달. 광역 index/MoC 스윕 제거.
2. **② index.md 통독 폐지**: 질의 경로에서 index 전량 read를 금지하고 search/concept-index로 대체. index는 린트·감사 전용.
3. **③ 오케스트레이터 프롬프트 슬림**: 후보 페이지 장황 나열·통독 지시 금지. 사전스코프 결과(slug 목록)만 전달, 발견·정독은 synthesizer에 위임.

## 3. 성공 지표 (측정 가능)

| 지표 | 현재(baseline) | 목표 |
|---|---|---|
| 질의당 index.md 전량 read | 1회 | **0회** |
| 질의당 페이지 read 수 | 12~19 | **≤ 6** (사전스코프 후보 + 근거 추적 여유) |
| 대표 질의 subagent_tokens | 52~62k | **≥30% 감소** |
| 답변 품질(신뢰도 병기·인용·환류 판단) | 유지 | **회귀 없음** |

측정: 동일 두 질의("사내 교육"·"차주 업무") 재실행 → tool_uses·subagent_tokens 비교. recall 체크(사전스코프 후보가 기존 답변의 핵심 근거 페이지를 포함하는지).

## 4. 비목표 / 제약

- 모델 교체 금지(synthesizer는 이미 sonnet — 더 낮추면 종합 품질 리스크, 최후 카드).
- 품질 하락 불가: 신뢰도 병기·출처 인용·`status: stale` 회피·환류 판단은 그대로.
- 크로스플랫폼 유지(search.py python·utf-8-sig·errors=replace).
- 결정적 스크립트는 LLM 토큰 0 유지.

## 5. 리스크 / 완화

| 리스크 | 완화 |
|---|---|
| 사전스코프가 관련 페이지 놓침(recall↓) | 후보 상한 넉넉히(8), synthesizer 부족 시 search 추가 허용, **스코프 신뢰도 명시+낮으면 추가search 의무화**(agy: unknown-unknowns). |
| grep 동의어/의미 매칭 실패(semantic gap) | 키워드 추출 시 **변형·동의어 다중 투입** + search.py가 **aliases도 검색**(agy 지적). 근본 한계는 잔존(수용). |
| 단순 매치수 정렬 왜곡(긴 템플릿 상위) | 정렬키를 **distinct-term 우선**으로(3/3 맞은 짧은 문서 > 1키워드 12번 긴 문서). (agy 지적) |
| Top 8 고정 컷오프 양면성(과소/노이즈) | --top은 **상한이지 채움 아님**, score>0만 → 구체 질의 소수·광역 최대 8. (agy 지적) |
| fallback MoC 선택에 index 재사용 → ②와 충돌 | MoC 선택은 **`ls wiki/moc/` 파일명 매칭**(0토큰), index 안 읽음. (agy 지적) |
| index 맥락(관계) 유실 | 현 index는 **평평 카탈로그**(관계 없음) — 관계는 페이지 `## 관계`·MoC 보유. 검증됨. (agy 지적) |
| 스킬 규칙만으론 미준수 | 오케스트레이터 흐름에 스크립트 호출을 명시 절차로 배선(프롬프트 아닌 단계). |
| 멀티턴 누적 토큰이 단판보다 클 수 있음 | 지표를 **end-to-end 누적 subagent_tokens**로 측정 → 누적 효과까지 포착. read 수 자체가 19→≤6로 감소하므로 턴↓. (agy 지적) |
